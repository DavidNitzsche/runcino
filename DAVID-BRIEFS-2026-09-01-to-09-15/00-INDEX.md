# Backend architecture review document map

Read in this order:

1. `BACKEND-DATA-BRAIN-APP-ARCHITECTURE-BRIEF.md` — target architecture and governing outcomes.
2. `WHOLE-BACKEND-MASTER-PLAN-AUDIT-2026-09-15.md` — clean-source and production-schema audit of the entire backend against that target.
3. `BACKEND-IMPLEMENTATION-SCOPE-AND-SETUP-2026-09-15.md` — executable release sequence, files, schemas, contracts, tests, rollout, compatibility, Railway setup, and gates.
4. `BACKEND-PROGRAMME-MANIFEST.json` — machine-readable unit/dependency/gate map.
5. `ASAP-IMPLEMENTATION-SEQUENCE.md` — original coarse sequence, retained as the incident-to-architecture outline; post-audit execution uses items 2–4 above.
6. `MASTER-PLAN-AUDIT-2026-09-15.md` — BA-01/build-303 audit against the original sequence.
7. `BA01-CODE-FORENSIC-2026-09-15.md` — remaining launch, route-cost, snapshot-generation, race-outlook, and false-offline causes.
8. `FIXES-AND-PROCESS-LOG.md` — chronological implementation and device evidence.
9. `ARCHITECTURE-PROPOSAL.md` — earlier proposal and incident analysis.
10. `research/` — supporting API, cron, caching, and architecture research.

`BACKEND-DATA-BRAIN-APP-ARCHITECTURE-BRIEF.md` owns the target. The whole-backend audit and implementation-scope document own the post-audit execution sequence. The changelog records events; it does not set readiness.
