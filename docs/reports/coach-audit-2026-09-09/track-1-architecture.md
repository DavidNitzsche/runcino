## 0. The not-yet-merged fix branch — `origin/fix/coach-voice-tie-and-primer`

`[SRC]` Diffed `main` against `origin/fix/coach-voice-tie-and-primer`
(commits `bc8010bbe`, `49be10229`, `7aacb0e36`) directly.

**What it fixes, confirmed against `main`'s actual code today:**

1. **TIEFIX-1.** `web-v2/lib/plan/generate.ts:16301-16312`'s `applyRunnerVoice`
   computes each week's "longest easy run" with a bare `>` comparison and one
   `{mi, iso}` slot per week (confirmed still present on `main` and on the
   audit worktree's `HEAD` per Track 2's/lib-plan tracker's own git check).
   A genuine tie (two easy days at the identical distance) silently resolves
   to "whichever day was scanned first," which is then told **"The week's
   longest easy run"** (`EASY_DAY_ROLE_LINES.volume`,
   `web-v2/lib/plan/runner-instruction.ts:404`) — false, since a second day
   tied it. The fix branch's own commit message cites this firing on 63% of
   weeks in the project's 8,781/98,822-archetype corpus (two slightly
   different counts appear across the three commits; the branch's own third
   commit is titled as a correction to this exact number, i.e. the branch
   author caught their own citation drift before merge — a good sign for the
   fix's rigor, irrelevant to whether it's safe to merge).
2. **PRIMER-SPECIFIC-1.** Once TIEFIX-1 stops awarding the `volume` role to
   one of two tied days, both tied days can fall through to `primer`
   (`EASY_DAY_ROLE_LINES.primer`, `runner-instruction.ts:407`,
   `"Short and easy. The session is tomorrow."`) — a **second** Rule 17
   violation (identical sentence twice in one week) that TIEFIX-1's own fix
   would have newly exposed. The branch adds `resolvePrimerLines` /
   `primerLineForNextSessionType` / `PRIMER_SESSION_LINE`
   (`runner-instruction.ts`, new in the diff) so a colliding second primer day
   gets a session-specific line naming what tomorrow's session actually is
   (`threshold`/`tempo`/`intervals`/`long`/`race`) instead of a repeat, falling
   back through a ladder (`specific → generic → PRIMER_COLLISION_FALLBACK`)
   that never repeats a sentence already spent that week.

**Assessment of the fix itself** `[SRC]`: both changes are additive,
narrowly scoped to `applyRunnerVoice`/`runner-instruction.ts`, reuse
`canonicalSessionType` (the one spelling authority in
`lib/training/workout-type.ts`) rather than re-deriving "what kind of session
is tomorrow," and are unit-tested (`_primer_specific.test.ts`,
`_sentence_repetition.test.ts`, `_layout_contract.test.ts` all touched). This
is a real, correctly-diagnosed pair of Rule 9 (discontinuity)/Rule 17
(repetition) defects, fixed in the doctrinally-correct place (the Plan
Generator's own row-authoring pass), not worked around downstream.

**Merge-safety flag — OUT OF SCOPE TO FIX, BUT MUST BE SURFACED.** `[SRC]`
`git diff main origin/fix/coach-voice-tie-and-primer --stat` shows this branch
is **also behind `main`** and would, if merged naively, **delete**:
`docs/PRODUCT_DECISIONS.md` (139 lines), two full audit docs
(`docs/audit-2026-09-09-canonical-handback.md`, 362 lines;
`docs/audit-2026-09-10-canonical-record.md`, 303 lines),
`docs/migration-166-review-packet.md` (250 lines), a native watch test file
(`_RecoveryEndedEarlyTests.swift`, 226 lines) and its production counterpart's
logic in `WorkoutEngine.swift` (103 lines removed), `RouteMapView.swift` (75
lines), `StaleStateV5.swift` (111 lines), most of `TodayAfterV5.swift` (76
lines), the watch-complete API route logic (`app/api/watch/workouts/complete/route.ts`,
70 lines), and several Xcode scheme/project files. This is the classic stale
parallel-session-branch hazard CLAUDE.md's "Branching & integration" section
warns about — the branch was cut before several rounds of unrelated work
landed on `main`, and a plain `git merge`/fast-forward would regress all of
it. **The correct move (not performed here, out of this audit's read-only
scope) is to cherry-pick only the two commits' `web-v2/lib/plan/generate.ts` +
`web-v2/lib/plan/runner-instruction.ts` + their new test files onto current
`main` in an isolated worktree, not merge the branch.**
